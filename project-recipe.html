recipegrind — Find recipes fast. Cook with what you have.

A web app with search and Pantry Mode: select ingredients and see what you can cook now.

Role End-to-end: research, UX/UI, frontend, backend
Timeline 2 weeks (MVP)
Tools Figma, React/TypeScript, MUI, TanStack Query, Node/Express, Prisma/Postgres, Render, GitHub Pages

Problem

Home cooks look through many recipes to find something they can make with the ingredients in their pantry.

Goals

Speed Cached results under 1s
Path “What can I cook now?” as a primary route
Clarity Steps and ingredients optimized for mobile

Research

  • 6 interviews; competitive scan (NYT Cooking, Allrecipes, Tasty)
  • People start from ingredients → Pantry as a top-level route
  • Time is a hard constraint → minutes slider + badges on cards
  • Users skim image + title → denser cards with small thumbnails

IA & Flows

Routes

  • Home (value prop)
  • Finder (keywords/filters)
  • Pantry (ingredients)
  • Detail (ingredients + steps)

Critical flows

  • Search → Results → Detail
  • Select ingredients → Results → Detail

Prototype & Testing

  • Interactive Figma prototype (desktop + mobile)
  • Usability: elevated Pantry to top nav and home CTA
  • Minutes slider gained live label; images switched to correct sizes

Build

Frontend

  • React + TypeScript + MUI
  • Hash Router for GitHub Pages
  • TanStack Query for data

Backend & Infra

  • Express proxy/cache to recipe API
  • Prisma + Postgres for favorites
  • API on Render; site on GitHub Pages

Impact

  • Pantry path reached recipe detail 2× faster than keyword search (pilot)
  • Users reported cooking with “what I already have”

Next

  • Favorites and shopping list
  • Nutrition details
  • PWA and offline cache
